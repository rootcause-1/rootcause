# CLAUDE.md — RootCause

You are building **RootCause**, an AI on-call agent for the **Graph Hacks: Context for AI Agents** hackathon (WeMakeDevs × FalkorDB), track **Agents That Act on Connected Data**. The hacking window is **15 Oct 2026, 12:01 AM IST → 18 Oct 2026, 11:59 PM IST**. Feature freeze: **18 Oct, 2:00 PM IST**.

RootCause turns live OpenTelemetry traces and metrics from the official OpenTelemetry Demo shop into a FalkorDB graph, finds the one real cause among many symptom alerts, proves it with an evidence path, fixes it with human approval, verifies recovery, writes the report, and remembers the incident.

The full product spec is `docs/PRD.md` (exported from the team's PRD doc). **If this file and the PRD disagree, ask a human before building.**

> **Start every session by reading §16 (current state).** All milestones are already coded; the job now is to run, verify, fix and ship — not to rewrite.

## 0. Non-negotiables (hackathon rules — breaking one can disqualify us)

1. **FalkorDB is the primary and only database**, and it must do real work. If the product would still work with FalkorDB removed, it is wrong. Never add Postgres, SQLite, Redis-as-cache, or in-memory dicts as a substitute for graph state. (Short-lived in-process buffers for the 5 s ingestion window are fine; the source of truth is the graph.)
2. **Every graph query lives in a named `.cypher` file** under `backend/rootcause/graph/queries/` and is listed in `docs/QUERIES.md` with its purpose. No inline Cypher strings in Python except trivial schema bootstrapping.
3. **Data must be allowed data**: only telemetry generated by the OpenTelemetry Demo on our machines, plus the synthetic seed file (teams, people, runbooks). Never load private or scraped data.
4. **README must contain**: setup instructions (live mode + replay mode), the graph data model (diagram + node/edge tables), the list of Cypher queries and graph algorithms, the track name, links to video and deployment.
5. **AI-assistant disclosure**: when you write or substantially change a module, append one line to `docs/AI_DISCLOSURE.md`: `date · module · what Claude Code did · what a human verified`. Keep it honest; humans fill the "verified" part.
6. **The team must be able to explain everything.** Prefer simple, readable code over clever code. Put a short docstring at the top of every module saying what it does and which graph queries it uses. After each milestone, write a 5-line "how it works" note in `docs/ARCHITECTURE.md`.
7. **Never fake results.** No hard-coded answers, no canned diagnoses keyed on flag names, no scorecard numbers typed by hand. The engine must never read the flagd config to decide a root cause (that would be cheating; the flag is ground truth for scoring only — see §9).

## 6. Graph model (implement exactly; full tables in `docs/GRAPH_MODEL.md`)

Graphs (FalkorDB multigraph): `rc_live`, `rc_replay`, `rc_eval_<runid>`. Pick via `RC_GRAPH`. Never mix.

Conventions:
- Every node has `id` (string, unique per label by convention) and an index: `CREATE INDEX FOR (n:Service) ON (n.id)` for every label below.
- Time = epoch **milliseconds** (int). Rates per second (float). Percentages as 0–1 floats.
- Node ids: services use the OTel `service.name` (e.g. `payment`, `checkout`, `frontend-proxy`). Queues `queue:orders`. Datastores `db:astronomy-db`, `cache:valkey-cart`. Incidents `INC-0001`. Alerts `ALT-<uuid8>`.

Nodes: `Service`, `Queue`, `Datastore`, `Container`, `Journey`, `Team`, `Person`, `Runbook`, `FeatureFlag`, `Change`, `Alert`, `Incident`, `SignalPattern`, `Hypothesis`, `Action`, `Prediction`, `Step`, `Report`, `ChaosRun`.

Relationships:
- `(Service)-[:CALLS {protocol, rps, err_rate, p95_ms, baseline_err, baseline_p95, last_seen}]->(Service)` and its mirror `(Service)-[:CALLED_BY]->(Service)` (kept in sync in the same query; used by `algo.bfs` for upstream walks).
- `(Service)-[:PRODUCES_TO {rate}]->(Queue)`, `(Queue)-[:CONSUMED_BY {rate, lag, group}]->(Service)`
- `(Service)-[:USES {p95_ms, err_rate}]->(Datastore)`
- `(Service)-[:RUNS_IN]->(Container)`
- `(Journey)-[:REQUIRES {share, critical}]->(Service)`
- `(Team)-[:OWNS]->(Service)`, `(Person)-[:MEMBER_OF]->(Team)`, `Person.on_call`
- `(Runbook)-[:FOR]->(Service)`, `(Runbook)-[:REMEDIATES]->(SignalPattern)`
- `(FeatureFlag)-[:AFFECTS]->(Service)`
- `(Change)-[:CHANGED]->(FeatureFlag|Container)`
- `(Alert)-[:FIRED_ON]->(Service|Queue|Datastore)`, `(Alert)-[:PART_OF]->(Incident)`
- `(Service|Queue|Datastore)-[:BLAMES {weight}]->(…)` — **transient**, rebuilt every tick, only between `:Anomalous` nodes
- `(Incident)-[:ROOT_CAUSE]->(node)`, `-[:CAUSED_BY]->(Change)`, `-[:IMPACTED {pct}]->(Journey)`, `-[:RESOLVED_BY]->(Action)`, `-[:HAS_SIGNAL]->(SignalPattern)`, `-[:SIMILAR_TO {score}]->(Incident)`, `-[:HAS_REPORT]->(Report)`, `-[:HAS_HYPOTHESIS]->(Hypothesis)`, `-[:INVESTIGATED_BY]->(Step)`
- `(Step)-[:NEXT]->(Step)`, `(Step)-[:CITED]->(any)`
- `(Prediction)-[:PREDICTS]->(Service|Journey)`, `(ChaosRun)-[:PRODUCED]->(Incident)`

Dynamic label: currently anomalous nodes also carry `:Anomalous`. Add with `SET n:Anomalous`, clear with `REMOVE n:Anomalous`. **VERIFY** label SET/REMOVE works on our FalkorDB version with a graph test. Fallback if not: rebuild a separate graph `rc_live_anomaly` each tick containing only anomalous nodes and BLAMES edges, and run WCC/PageRank there.

Seed (`config/seed.yaml`): teams (`payments-team`, `storefront-team`, `platform-team`, `data-team`, `ai-team`), 2 people each with one `on_call: true`, ownership of every demo service, journeys (`browse`, `view_product`, `add_to_cart`, `checkout`, `ask_assistant`) with the HTTP routes that identify their root spans (VERIFY routes from Jaeger), runbooks per service, and a fallback flag→service map. All names are invented.

## 7. Ingestion, detection and the engine

### 7.1 Spans (`ingest/otlp.py`, `ingest/spans.py`)
- Parse OTLP JSON: `resourceSpans[].resource.attributes` (get `service.name`), `scopeSpans[].spans[]` with `traceId`, `spanId`, `parentSpanId`, `name`, `kind` (int: 2 SERVER, 3 CLIENT, 4 PRODUCER, 5 CONSUMER; accept string enums too), `startTimeUnixNano`, `endTimeUnixNano` (strings), `status.code` (2 = ERROR), `attributes`.
- Keep a 60 s sliding window in memory keyed by trace. On each tick:
  - **Call edges**: for a CLIENT span in service A whose child SERVER span is in service B → edge A→B. If no child server span exists, use `peer.service` / `server.address` / `rpc.service` attributes to name B and mark the call `unanswered`.
  - **Messaging**: PRODUCER spans → `PRODUCES_TO`, CONSUMER spans → `CONSUMED_BY`; per-queue produce and consume rates from span counts.
  - **DB/cache**: CLIENT spans with `db.system` → `USES` edge to `db:<db.name or system>`.
  - **Self-error**: an error span whose children (in the window) are all non-error → counts as a self error for its service. `self_err_rate = self_errors / server_spans`.
  - **Journeys**: root spans (no parent) at the frontend/proxy matched by route → journey success rate; services touched in that trace → `REQUIRES {share}`.
  - **Agent runs**: per `astronomy_shop_agent_workflow` span, count child tool-call and LLM spans and LLM latency → properties on `Service {id:'agent'}`: `tool_calls_per_run`, `llm_p95_ms`.
- Write with batched `UNWIND` queries (`upsert_services.cypher`, `upsert_calls.cypher`, `upsert_messaging.cypher`, `upsert_journeys.cypher`). One round trip per query per tick.

### 7.2 Metrics (`ingest/prom.py`, `ingest/docker_stats.py`)
- PromQL with names from `config/rootcause.yaml` only (discovered, never guessed): Kafka consumer lag per group, runtime memory per service.
- `docker stats` (non-streaming) for every demo container each tick: CPU %, memory MB, memory slope (MB/min over 2 min). Map container → service by compose service name.
- Docker events → `(:Change {kind:'restart'})` linked to the container.

### 7.3 Changes (`ingest/flag_watcher.py`)
- Poll the flagd JSON every 2 s; on any `defaultVariant` change create `(:Change {kind:'flag', from, to, ts, actor:'unknown'})-[:CHANGED]->(:FeatureFlag)`. Actor is `rootcause` when we made the change.
- **The engine may use the existence and timing of a Change, never the flag→truth mapping from the chaos catalogue.**

### 7.4 Baselines and alerts (`detect/`)
- EWMA per metric (α = 0.1), learned during the first 180 s of healthy traffic, then frozen while any incident is open.
- Rules (thresholds in `rootcause.yaml`), each must hold for 2 consecutive ticks:
  - `error_rate`: err_rate > max(baseline + 3σ, baseline + 0.05)
  - `latency`: p95 > 2 × baseline_p95 and > 50 ms
  - `lag`: lag slope > 0 for 30 s, or consume_rate < 20% of produce_rate
  - `memory`: memory slope > `mem_slope_mb_per_min` (start at 5) for 2 min
  - `cpu`: cpu_pct > 85
  - `agent_loop`: tool_calls_per_run > 3 × baseline; `llm_latency`: llm_p95 > 2 × baseline
- Alert → `(:Alert)-[:FIRED_ON]->(node)`, node gains `:Anomalous`, `SignalPattern {id:'<node>:<kind>'}` is merged. Alerts resolve after 3 healthy ticks.

### 7.5 Engine (`engine/`) — key queries (FalkorDB Cypher; keep each in its own file)

`rebuild_blames.cypher` (run as 3 statements):
```cypher
MATCH ()-[b:BLAMES]->() DELETE b
```
```cypher
MATCH (a:Anomalous)-[r:CALLS|USES]->(b:Anomalous)
CREATE (a)-[:BLAMES {weight: coalesce(r.err_rate, 0.0) + 0.01}]->(b)
```
```cypher
MATCH (q:Queue:Anomalous)-[:CONSUMED_BY]->(c:Anomalous)
CREATE (q)-[:BLAMES {weight: 1.0}]->(c)
```
(Async edges never blame upstream: a lagging queue blames its consumer, not its producer.)

`group_incidents.cypher`:
```cypher
CALL algo.WCC({nodeLabels: ['Anomalous'], relationshipTypes: ['BLAMES']})
YIELD node, componentId
RETURN componentId, collect(node.id) AS members
```
Match components to open incidents by member overlap (keep incident ids stable across ticks); new component → new `Incident`.

`pagerank_blame.cypher`:
```cypher
CALL algo.pageRank('Anomalous', 'BLAMES')
YIELD node, score
RETURN node.id AS id, score
```

`blame_depth.cypher`:
```cypher
MATCH (v:Anomalous) WHERE v.id IN $members
OPTIONAL MATCH (v)-[:BLAMES]->(d:Anomalous)
RETURN v.id AS id, count(d) AS out_degree
```

`recent_changes_for.cypher`:
```cypher
MATCH (c:Change)-[:CHANGED]->(f:FeatureFlag)-[:AFFECTS]->(s)
WHERE s.id = $node_id AND c.ts >= $onset - $window_ms AND c.ts <= $onset + 30000
RETURN c.id AS change, f.id AS flag, c.from AS from, c.to AS to, c.ts AS ts
ORDER BY c.ts DESC
```
(plus a second query for `Change`→`Container`←`RUNS_IN`←`Service`)

Ranking (`engine/ranking.py`), all components normalised to 0–1:

```
score = 0.30*depth + 0.25*self + 0.20*pagerank + 0.15*change + 0.10*memory
depth  = 1.0 if out_degree == 0 else 0.5 ** out_degree
self   = self_err_rate normalised in the incident, or the anomaly z-score (capped at 1) for non-error signals
change = 1.0 if a Change hits the node within 10 min before onset (0.5 if within 30 min)
memory = best similarity of a resolved past incident whose ROOT_CAUSE was this node
```
Weights live in `rootcause.yaml`. Store each candidate as `(:Hypothesis {target, score, rank, method_scores})`. Tune weights only on recorded scenarios, never by looking at the chaos catalogue at run time.

Edge causes (`engine/edge_cause.py`): if caller A has failing/unanswered client spans to B and B has **zero server spans** in the window while it had traffic in the baseline, add a hypothesis `edge:A->B` with self = 1.0. It is scored against truth `checkout->payment` for `paymentUnreachable`.

`impact_journeys.cypher`:
```cypher
MATCH (j:Journey)-[r:REQUIRES]->(s)
WHERE s.id IN $failing
RETURN j.id AS journey, j.success_rate AS now, j.baseline AS baseline, collect(s.id) AS via
```

`evidence_path.cypher` (VERIFY the shortestPath form FalkorDB accepts; fall back to `algo.SPpaths` if needed):
```cypher
MATCH (a {id: $from}), (b {id: $to})
WITH a, b
MATCH p = shortestPath((a)-[:BLAMES*1..8]->(b))
RETURN [n IN nodes(p) | n.id] AS path
```

`upstream_bfs.cypher` (blast radius and prediction):
```cypher
MATCH (x {id: $id})
CALL algo.bfs(x, $depth, 'CALLED_BY') YIELD nodes, edges
RETURN [n IN nodes | n.id] AS upstream
```

`service_betweenness.cypher`:
```cypher
CALL algo.betweenness({nodeLabels: ['Service'], relationshipTypes: ['CALLS'], samplingSize: 64, samplingSeed: 42})
YIELD node, score
RETURN node.id AS id, score
```

`similar_incidents.cypher`:
```cypher
MATCH (cur:Incident {id: $id})-[:HAS_SIGNAL]->(sp:SignalPattern)<-[:HAS_SIGNAL]-(past:Incident)
WHERE past.status = 'resolved' AND past.id <> cur.id
WITH cur, past, count(sp) AS shared
MATCH (cur)-[:HAS_SIGNAL]->(a)
WITH cur, past, shared, count(a) AS ca
MATCH (past)-[:HAS_SIGNAL]->(b)
WITH past, shared, ca, count(b) AS cb
OPTIONAL MATCH (past)-[:RESOLVED_BY]->(act:Action)
RETURN past.id AS incident, toFloat(shared) / (ca + cb - shared) AS jaccard, collect(act.kind + ':' + act.target) AS fixes
ORDER BY jaccard DESC LIMIT 3
```
Add +0.1 when the past `ROOT_CAUSE` equals the current top hypothesis; cap at 1.0. ≥ 0.6 = "strong match": propose its fix first.

Prediction rules (`engine/predict.py`): walk upstream via `CALLED_BY`; a sync edge (`grpc`/`http`) propagates "errors", an async edge (Kafka) propagates nothing upstream and "lag" downstream; journeys whose `REQUIRES` set intersects predicted-failing services with `critical = true` are predicted broken. Save `(:Prediction)-[:PREDICTS]->(…)`; after the break compute precision/recall vs `:Anomalous` set.

Safety (`engine/safety.py`): for each candidate action produce `{risk, affected_services, affected_journeys, stateful, reason}`:
- flag revert on a flag that `AFFECTS` the root: risk `low`, affected = services the flag affects.
- container restart: affected = `upstream_bfs` of the service + its journeys; stateful if it `USES` a cache/db holding sessions (cart); risk from betweenness percentile (`high` if top 20% or stateful).
- page team: risk `none`.
Order proposals by risk, then expected effectiveness. `high` needs typed confirmation (`RESTART <service>`).

## 9. Actions, verification, chaos and scorecard

Actions:
- `flagd.set_variant(flag, variant)`: read JSON, change `defaultVariant`, write to temp file + `os.replace` (atomic). Record `(:Action)` and the resulting `(:Change {actor:'rootcause'})`.
- `containers.restart(service)`: Docker SDK restart of the mapped container.
- `pager.page(team, incident)`: append to `data/pager_inbox.jsonl` (shown in UI) and POST to `PAGER_WEBHOOK_URL` if set.
- `verify.watch(incident)`: success when every alert in the incident is resolved for 3 ticks within `verify.timeout_seconds` (150 s; 90 s was too tight: the 60 s error window has to drain first) → `Action.status='verified'`, `Incident.status='resolved'`, `ttr_ms` set; otherwise `failed` and the agent proposes the next action.
- `report.write(incident)`: gather facts with queries (timeline, path, change, impact, action, similar incidents), LLM narrates if enabled, else a template. Save `(:Report)` + `reports/INC-xxxx.md`.

Chaos runner (`chaos/runner.py`), one run:
1. Ensure all flags default `off`; wait until no open incidents and 60 s healthy.
2. Pick a random catalogue entry (seeded RNG, logged). Set its variant. **Do not tell the engine** (no API call, no graph write except the flag watcher's normal `Change`).
3. Wait up to 180 s for an incident whose agent verdict is final. Record top-3 hypotheses, time from flip to verdict.
4. Revert the flag (as the harness, not the agent), wait for recovery.
5. Score: truth from `catalogue.yaml`; `top1`, `top3`, `ttd_ms`; also run each baseline on the same alerts snapshot:
   - `loudest_alert`: node with most alerts; `first_alert`: earliest alert's node; `highest_error`: max err_rate;
   - `llm_no_graph`: same LLM, given only a flat table of alerts and per-service metrics, no tools;
   - `graph_off`: our ranking with PageRank, depth, change and memory disabled (self signal only).
6. Write `(:ChaosRun)` in `rc_eval_<batch>` and append to `docs/SCORECARD.md` (table per method: top-1, top-3, median TTD, plus a per-class breakdown: errors / latency / invisible / AI agent, and a list of misses with reasons).

`chaos/catalogue.yaml` format (fill from day-1 observations; the human confirms):
```yaml

  truth: payment
  class: errors
- flag: paymentUnreachable
  variant: "on"
  truth: "edge:checkout->payment"
  class: errors
```

## 15. Gotchas

- FalkorDB speaks the Redis protocol with `GRAPH.QUERY`/`GRAPH.RO_QUERY`; it is **not** Neo4j. No APOC, no `dbms.*`, no Neo4j-only procedures. Check `docs.falkordb.com/cypher` before using an unusual clause.
- Algorithm signatures (FalkorDB docs): `algo.pageRank(label, relType) YIELD node, score`; `algo.betweenness({nodeLabels, relationshipTypes, samplingSize, samplingSeed}) YIELD node, score`; `algo.bfs(startNode, maxDepth, relType) YIELD nodes, edges`; `algo.WCC({nodeLabels, relationshipTypes}) YIELD node, componentId`. Use a fixed `samplingSeed` for reproducibility.
- Always pass values as query parameters, never by string formatting.
- OTLP JSON uses strings for 64-bit nanosecond timestamps; convert with `int(s) // 1_000_000`.
- Span pairing must tolerate missing children (sampling, cross-batch timing): keep traces for 2 ticks before finalising.
- Do not count the load generator, flagd, the collector or RootCause itself as candidate root causes (keep a `non_candidates` list in config).
- Some faults are partial (`adFailure` 10%, `productCatalogFailure` one product, `intlShippingSlowdown` non-US only). Use rates, not counts, and keep the error-rate floor low enough to catch 10%.
- The flagd config edit must keep valid JSON; validate before replacing the file.
- Keep the UI usable when the graph is empty (first 3 minutes of baseline learning: show "Learning baseline… 2:10 left").
- Port clashes: the demo uses 8080 (proxy) and its own internal ports. Map FalkorDB's browser to host **3300** and Redis protocol to host **6380**; inside the Docker network keep `falkordb:6379`. Our API on host 8000, UI on 5173 (dev) / 8088 (built), MCP HTTP on 8811.
- When you are unsure whether something is cheating (e.g. reading the flag to pick a root), it is. Ask.

### FalkorDB behaviour verified by running the graph tests (module 4.18.3)
- `shortestPath` is only allowed inside `WITH`/`RETURN`, never in `MATCH p = shortestPath(...)` (fixed in `evidence_path.cypher`).
- **`algo.WCC` silently drops its filters when a label or relationship type in them does not exist in the graph yet** and then runs over the whole graph (seed teams, runbooks, flags…). `engine/grouping.py` guards this with `anomalous_nodes` + `blames_count`; keep that guard. Apply the same guard to any new `algo.*` call whose filter label/type can be absent. `algo.pageRank(label, rel)` returns no rows in that case (safe).
- `SET n:Anomalous` / `REMOVE n:Anomalous`, `SET n += $map`, map literals in `collect({...})`: all work (tests pass).
- Pin the Docker image once the graph tests pass against it: replace `falkordb/falkordb:latest` in both compose files with the exact tag you tested (`docker image inspect` → version), so a new release can't break the demo.
